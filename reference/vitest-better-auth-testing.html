Reference: Vitest & Better Auth Mocking Patterns

Quick reference guide for test helpers, module mocking, and type casting

1. The Core Concepts

  • Why mock auth? Server Actions depend on auth.api.getSession(). In unit tests, we simulate logged-in and logged-out states without reaching a real database or browser cookie engine.
  • vi.mock("@/lib/auth"): Tells Vitest to intercept imports of @/lib/auth and substitute mock functions.
  • vi.mocked(fn): A TypeScript-only wrapper that exposes mock methods (like mockResolvedValue) on typed functions without manual as unknown as Mock casting.

2. Pattern Comparison Cheat Sheet

Option A: Direct vi.mocked in Test Setup

// 1. Mock module
vi.mock("@/lib/auth", () => ({
  auth: { api: { getSession: vi.fn() } }
}));

// 2. Set return value in test
vi.mocked(auth.api.getSession).mockResolvedValue({
  user: { id: "user-1", email: "user@example.com" },
  session: { id: "sess-1", userId: "user-1", expiresAt: new Date() }
} as any);

Best for: One-off tests needing bespoke user objects or testing edge-case user properties.

Option B: Shared Helper (e.g. mockSession(user))

// In src/test/utils.ts
export function mockSession(user: { id: string; email?: string } | null = { id: "user-1" }) {
  if (!user) {
    vi.mocked(auth.api.getSession).mockResolvedValue(null);
    return;
  }
  vi.mocked(auth.api.getSession).mockResolvedValue({
    user: { id: user.id, email: user.email ?? `${user.id}@example.com` },
    session: { id: `sess-${user.id}`, userId: user.id, expiresAt: new Date() },
  } as any);
}

// In test files:
describe("Server Actions", () => {
  beforeEach(() => {
    mockSession({ id: "user-1" }); // default auth state
  });

  it("rejects when unauthenticated", async () => {
    mockSession(null);
    await expect(myAction()).rejects.toThrow("Unauthorized");
  });
});

Best for: Multi-file test suites (like goals.test.ts, transactions.test.ts, friends.test.ts, groups.test.ts) to keep tests DRY and readable.
